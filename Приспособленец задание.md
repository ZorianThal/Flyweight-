# Практическое задание

## Паттерн Flyweight (Приспособленец)

### Задача

Разработать небольшую систему управления объектами городской карты.

На карте должно находиться большое количество объектов:

- магазины;
    
- аптеки;
    
- кафе;
    
- больницы;
    
- автозаправочные станции.
    

Каждый объект должен иметь собственные координаты и адрес, но объекты одной категории должны использовать **общий объект стиля**.

Например, все аптеки используют один `MarkerStyle`, все кафе — другой.

---

## 1. Структура проекта

Проект должен иметь следующую структуру:

```
CityMap/
│
├── Models/
│   ├── MapMarker.cs
│   └── MarkerStyle.cs
│
├── Factories/
│   └── MarkerStyleFactory.cs
│
├── Services/
│   └── MapService.cs
│
└── Program.cs
```

Дополнительные классы можно создавать при необходимости.

---

## 2. Класс MarkerStyle

Создать класс `MarkerStyle`.

Он должен содержать общую информацию об определённой категории объектов:

```
Category
Icon
Color
```

Например:

```
Категория: Аптека
Иконка: pharmacy.png
Цвет: Green
```

Объект `MarkerStyle` должен создаваться только тогда, когда такого стиля ещё нет.

---

## 3. Класс MapMarker

Создать класс `MapMarker`.

Каждый маркер должен содержать:

```
Address
Latitude
Longitude
```

Также маркер должен хранить ссылку на `MarkerStyle`.

Пример:

```
Аптека
Адрес: ул. Ленина, 15
Координаты: 54.7104, 20.4522
```

Маркер не должен самостоятельно создавать `MarkerStyle`.

---

## 4. MarkerStyleFactory

Создать класс:

```
MarkerStyleFactory
```

Фабрика должна хранить уже созданные стили.

Для хранения использовать:

```
Dictionary<string, MarkerStyle>
```

Если стиль категории уже существует, фабрика должна вернуть существующий объект.

Если стиля ещё нет — создать его, сохранить и вернуть.

Например:

```
GetStyle("Аптека")
        ↓
существует?
   ├── Да → вернуть существующий MarkerStyle
   │
   └── Нет → создать → сохранить → вернуть
```

---

## 5. MapService

Создать сервис управления картой.

Он должен содержать коллекцию:

```
List<MapMarker>
```

Реализовать методы:

```
AddPharmacy()
AddCafe()
AddShop()
AddHospital()
AddGasStation()
DisplayMap()
```

При добавлении каждого объекта сервис должен получать соответствующий `MarkerStyle` через `MarkerStyleFactory`.

Запрещается создавать `MarkerStyle` непосредственно внутри `MapMarker`.

---

## 6. Program.cs

`Program.cs` должен использовать современный синтаксис C# без самостоятельно написанного:

```
static void Main()
```

В `Program.cs` необходимо:

1. Создать `MarkerStyleFactory`.
    
2. Создать `MapService`.
    
3. Добавить минимум:
    
    - 5 аптек;
        
    - 5 кафе;
        
    - 5 магазинов;
        
    - 3 больницы;
        
    - 3 АЗС.
        
4. У каждого объекта должны быть разные координаты.
    
5. Вывести информацию о карте.
    

---

## 7. Главное требование Flyweight

В программе должно существовать только:

```
1 MarkerStyle для аптек
1 MarkerStyle для кафе
1 MarkerStyle для магазинов
1 MarkerStyle для больниц
1 MarkerStyle для АЗС
```

При этом объектов `MapMarker` должно быть значительно больше.

Получается:

```
20+ MapMarker
       │
       ├──────────► MarkerStyle "Аптека"
       │
       ├──────────► MarkerStyle "Кафе"
       │
       ├──────────► MarkerStyle "Магазин"
       │
       ├──────────► MarkerStyle "Больница"
       │
       └──────────► MarkerStyle "АЗС"
```

---

## 8. Проверка работы Flyweight

Добавить в программу проверку, доказывающую, что одинаковые категории действительно используют один объект.

Например, получить два стиля:

```
MarkerStyle style1 = factory.GetStyle(...);
MarkerStyle style2 = factory.GetStyle(...);
```

и проверить:

```
ReferenceEquals(style1, style2)
```

Результат должен быть:

```
True
```

Это означает, что обе переменные указывают на один и тот же объект.

---

## 9. Дополнительная часть

Добавить возможность подсчитать количество созданных стилей.

Например:

```
Всего объектов на карте: 25
Создано стилей: 5
```

Количество объектов карты должно быть большим, чем количество объектов `MarkerStyle`.

---

## 10. Ограничения

Запрещается:

- создавать новый `MarkerStyle` для каждого `MapMarker`;
    
- хранить `Icon`, `Color` и `Category` непосредственно в каждом `MapMarker`;
    
- создавать стили напрямую внутри `MapMarker`;
    
- использовать `if`/`switch` для проверки конкретного типа объекта в `MapMarker`;
    
- помещать всю программу в один `.cs` файл;
    
- переносить всю логику в `Program.cs`;
    
- создавать отдельный класс для каждой отдельной аптеки, кофейни или магазина.
    

---

## 11. Результат

После выполнения задания проект должен демонстрировать следующую архитектуру:

```
                    Program
                       │
                       ▼
                  MapService
                       │
                       ▼
              MarkerStyleFactory
                       │
             ┌─────────┼─────────┐
             ▼         ▼         ▼
          Pharmacy    Cafe      Shop
             │         │         │
             └─────────┼─────────┘
                       ▼
                  MarkerStyle
```

При этом:

```
MapMarker
    ↓
уникальные данные

MarkerStyle
    ↓
общие данные

MarkerStyleFactory
    ↓
повторное использование общих объектов
```

Главная цель работы — показать, что **Flyweight позволяет не создавать одинаковые объекты повторно, а разделять общее состояние между множеством объектов.**
